## 逐页讲述提示

### 1　项目简介

这个模拟器读取 `.yo` 中的机器码，按照 Y86-64 指令集逐条执行。每条指令结束后，记录 PC、寄存器、条件码、内存和机器状态。实现采用顺序非流水线架构，接下来用数据流说明各阶段之间如何配合。

### 2　指令分类

按功能可以分为数据传送、算术逻辑、控制转移、栈与函数调用、运行控制。数据传送包含寄存器间传送、立即数传送和内存读写。OPq 包含加、减、与、异或四种运算。jXX 包含无条件跳转和六种条件跳转。pushq、popq、call、ret 都隐式使用栈指针。

汇报可按 11 组讲述：`rrmovq/cmovXX`、`irmovq`、`rmmovq`、`mrmovq`、`OPq`、`jXX`、`call`、`ret`、`pushq`、`popq`、`halt/nop`。从机器编码看，`halt` 和 `nop` 的操作码不同，合法 `icode` 是 `0x0` 到 `0xB`，共 12 个值。分类方式与操作码计数需要区分。

### 3　六阶段数据通路

取指从 PC 读取字节，得到操作码、功能码、寄存器编号、立即数和顺序下一地址。译码只负责读取源寄存器，保存到 `valA`、`valB`。执行阶段计算算术结果或有效地址，必要时更新条件码和 `Cnd`。访存读写 8 字节。写回把 ALU 结果和内存结果写进目标寄存器。最后从顺序地址、分支目标和返回地址中选择下一个 PC。

`PC`、`REG`、`CC`、`MEM`、`STAT` 是机器状态；`valA`、`valB`、`valE`、`valM` 等是当前指令的阶段间暂存值。六阶段描述处理顺序，这个软件实现没有给出真实硬件的周期性能结论。

### 4　各类指令的数据流

寄存器传送在译码读出 `valA`，执行时把它传给 `valE`，写回阶段再检查条件。立即数传送直接使用取指得到的 `valC`。内存传送先计算基址加偏移量，再进行读或写。`OPq` 的操作数顺序是 `valB op valA`，特别是 `subq` 必须计算 `valB - valA`。

`jXX` 不写寄存器，执行阶段只产生条件判断，更新 PC 时才选择分支。`call` 把 `valP` 压栈后跳到 `valC`。`ret` 从栈中读出 `valM`，把它作为返回地址。`halt` 在取指阶段设置 HLT 并停止，`nop` 只顺序前进。

### 5　64 位运算与条件判断

Python 的整数不会自然限制在 64 位，因此 `uint64()` 用掩码保留低 64 位。寄存器内部保存无符号形式，输出快照时转成有符号补码，便于与标准答案比较。

ZF 表示截断结果为零，SF 取结果最高位。对于加减法，先把输入解释成有符号整数，计算完整结果，再检查是否超出 `[-2^63, 2^63-1]`。位运算把 OF 清零。以最大正数加一为例，结果最高位变成 1，同时 OF 也为 1。判断有符号“小于”时用 `SF ^ OF`，才能在溢出时得到正确比较关系。

### 6　栈指针的特殊语义

理解这两个例子要抓住“读旧值”和“写回顺序”。`pushq %rsp` 在译码阶段就保存旧 `%rsp`。执行阶段虽然已经计算出 `%rsp - 8`，访存写入的数据仍来自 `valA`，所以压入旧栈指针。

`popq %rsp` 同时产生两个寄存器写回：栈指针加 8，以及内存读出的值。实现先写 `valE`，后写 `valM`。目标相同时，内存值成为最终的 `%rsp`。这说明同一条指令的多个写回也有明确次序。

### 7　异常处理

取指遇到 halt、非法编码或越界时，后续阶段不执行。数据访存越界则由 `read_mem()`、`write_mem()` 设置 ADR。非法读取返回 0，非法写入不修改内存。

本题模板明确要求：`memory_stage()` 产生 ADR 后，仍调用 `write_back()`，然后在 `update_pc()` 前停止。因此 `%rsp = 0` 时压栈会禁止非法写入，但栈指针仍写回为 64 位补码 `−8`，PC 留在出错指令的位置。讲解时需要把这条课程约定说清楚。

### 8　绝对值求和程序

演示文件为 `test/abs-asum-cmov.yo`。入口把栈指针设为 `0x200`，在 `0x00A` 调用 `0x038` 的 main。main 把数组首址 `0x018` 放入 `%rdi`，把长度 4 放入 `%rsi`，再调用 `0x056` 的 absSum。

函数清空累加器，然后跳到 `0x08D` 检查计数。计数非零就跳到 `0x077`。每轮读取一个元素到 `%r10`，计算其相反数到 `%r11`，由 `cmovg` 判断是否需要采用相反数，再把绝对值加入 `%rax`。随后地址增加 8，计数减 1。`cmovg` 不改变顺序执行路径，PC 仍更新为 `valP`。

第四轮结束后，`jne` 不再跳转。`0x096` 的 ret 返回到 main 的 `0x055`，随后 main 返回到 `0x013` 的 halt。

## 六阶段源码问答

### Fetch：取指

**输入和输出是什么？** 输入为 PC 和内存。输出为 `icode`、`ifun`、`rA`、`rB`、`valC`、`valP`。

**如何计算指令长度？** 从 `PC + 1` 开始，存在寄存器字节时加 1，存在常数时再加 8。结果存为 `valP`。因此 halt/nop/ret 为 1 字节，寄存器传送、OPq、pushq/popq 为 2 字节，jXX/call 为 9 字节，立即数传送与两种内存传送为 10 字节。

**如何验证指令？** 先检查 `icode` 是否属于 0 到 11，再按指令限制 `ifun`。条件传送与跳转允许 0 到 6，OPq 允许 0 到 3，其他指令只允许 0。读取寄存器字节后验证寄存器位置。`irmovq` 的 rA、pushq/popq 的 rB 必须为 RNONE。

**RNONE 是什么？** 编码 15，表示不存在寄存器。译码返回 0，写回忽略它。内存传送允许 rB=RNONE，实现以 `valC` 为绝对地址的寻址形式。

**为什么每次取指重置 rA/rB/valC？** 不含这些字段的指令不能沿用前一条指令的暂存值。

### Decode：译码

**为什么不立即修改寄存器？** 后续阶段需要同一条指令开始时的寄存器值，例如 pushq %rsp 必须保存旧值。

**源寄存器怎样选择？** 寄存器传送、存内存、OPq、pushq 的 `srcA=rA`。popq/ret 的 `srcA=RSP`。内存传送与 OPq 的 `srcB=rB`。四种栈与调用指令的 `srcB=RSP`。

### Execute：执行

**为什么没有为所有指令写独立的 ALU？** 通过选择 `aluA` 和 `aluB` 复用加法通路。传值取另一操作数为 0，访存取偏移量和基址，栈操作取 ±8 和旧栈指针。只有 OPq 按 ifun 选择四种运算。

**减法是谁减谁？** `subq rA, rB` 的结果为 `R[rB] - R[rA]`，写回 rB。

**哪类指令更新条件码？** 只有 OPq。地址计算、栈指针加减、数据传送均保留原条件码。

**为什么使用完整有符号结果检查 OF？** 本实现保留完整有符号结果，并在截断前检查其范围。也可以通过操作数和截断结果的符号位关系判断溢出。

### Memory：访存

**为什么 popq/ret 用 valA 作地址？** valA 保存旧栈指针；valE 已经是栈指针加 8。弹出的数据位于旧栈顶。

**call 写入什么？** 写入 `valP`，也就是 call 后一条指令的地址，供 ret 恢复控制流。

**内存采用什么数据结构？** `bytearray(8192)`。8 字节数据用 `struct` 按小端读写，内存访问检查整个区间是否在边界内。

### Write Back：写回

**为什么需要 dstE 和 dstM？** 一条指令最多分别写入 ALU 结果和内存结果，例如 popq 更新栈指针并写入目标寄存器。

**条件传送失败怎么办？** 让 `dstE=RNONE`，不修改目标寄存器；PC 仍按顺序更新。

**发生 ADR 为什么还写回？** 这是作业模板规定的主循环顺序，决定异常快照的可观察状态。不能在访存阶段后自行提前跳过 write_back。

### Update PC：更新程序计数器

**有几个候选值？** `valP` 是顺序后继地址，`valC` 是 call 或跳转目标，`valM` 是 ret 从栈取出的返回地址。

**分支目标越界在何时报告？** 本条跳转先更新 PC，下一轮 fetch 检查该 PC 并产生 ADR。

**halt 的 PC 为什么不加一？** halt 在 fetch 设置 HLT，主循环直接保存快照并停止，没有进入 update_pc。

## 逐指令六阶段对照

下表中 `R[r]` 表示寄存器值，`M8[a]` 表示地址 a 处的小端 8 字节值，所有 ALU 结果按 64 位截断。未列出的写操作不发生。正常执行时，除 OPq 外均保留条件码。

| 指令 | Fetch | Decode | Execute | Memory | Write Back | Update PC |
|---|---|---|---|---|---|---|
| `rrmovq / cmovXX rA,rB` | 寄存器字节，`valP=PC+2` | `valA=R[rA]` | `valE=valA`，计算 Cnd | 无 | Cnd 成立时 `R[rB]=valE` | `valP` |
| `irmovq V,rB` | 寄存器字节与 valC，`valP=PC+10` | 无 | `valE=valC` | 无 | `R[rB]=valE` | `valP` |
| `rmmovq rA,D(rB)` | 寄存器字节与 valC，`valP=PC+10` | `valA=R[rA]`，`valB=R[rB]` | `valE=valB+valC` | `M8[valE]=valA` | 无 | `valP` |
| `mrmovq D(rB),rA` | 寄存器字节与 valC，`valP=PC+10` | `valB=R[rB]` | `valE=valB+valC` | `valM=M8[valE]` | `R[rA]=valM` | `valP` |
| `OPq rA,rB` | 寄存器字节，`valP=PC+2` | `valA=R[rA]`，`valB=R[rB]` | `valE=valB op valA`，更新 CC | 无 | `R[rB]=valE` | `valP` |
| `jXX Dest` | valC，`valP=PC+9` | 无 | 由 CC 计算 Cnd | 无 | 无 | Cnd 成立选 valC，否则 valP |
| `call Dest` | valC，`valP=PC+9` | `valB=R[RSP]` | `valE=valB-8` | `M8[valE]=valP` | `R[RSP]=valE` | `valC` |
| `ret` | `valP=PC+1` | `valA=valB=R[RSP]` | `valE=valB+8` | `valM=M8[valA]` | `R[RSP]=valE` | `valM` |
| `pushq rA` | 寄存器字节，`valP=PC+2` | `valA=R[rA]`，`valB=R[RSP]` | `valE=valB-8` | `M8[valE]=valA` | `R[RSP]=valE` | `valP` |
| `popq rA` | 寄存器字节，`valP=PC+2` | `valA=valB=R[RSP]` | `valE=valB+8` | `valM=M8[valA]` | 先 `R[RSP]=valE`，再 `R[rA]=valM` | `valP` |
| `nop` | `valP=PC+1` | 无 | 无架构状态变化 | 无 | 无 | `valP` |
| `halt` | `STAT=HLT` | 停止 | 停止 | 停止 | 停止 | PC 保留 |

异常规则优先于表中的正常执行路径：取指失败直接停止；数据访存失败仍执行写回，随后保留 PC 并停止。内存传送 rB=RNONE 时，基址按 0 处理。
